# 开发笔记

写给接手这个项目的人。这里只记**从代码里看不出来**的东西：为什么这么做、踩过哪些坑、哪些地方还欠着。
怎么运行、目录结构、图集格式见 [README](../README.md)。

## 1. 项目的边界

- **是同类玩法的原创游戏，不是某款老游戏的复刻。** 起因是想重现「没有等级、武功靠用出来」的经典武侠网游体验，但名字、地图、NPC、怪物、界面、美术全部是新做的。往后加内容也守这条线：可以借鉴玩法机制，不照搬具体作品的名称与形象。
- **运行时是实时 3D。** 最初的版本是「3D 预渲染成 2D 贴图 + 实时 2D 光照」，需求方当时明确不要 3D。后来的验收结论是画面「比一般 2D 游戏好一点，但比 3A 差远了」，要的是暗黑破坏神那样的光影；动态阴影、透视纵深这些在贴图精灵上只能近似，于是整个渲染层推翻重做成实时 3D（three.js）。玩法、数值、界面、地图数据没有动。
- **只做单机 demo**，不联网。目标是在浏览器里体现玩法与画面，不是完整游戏。
- **模型全部由代码程序化生成，贴图允许用 CC0 素材。** 没有模型文件，也没有第三方音频；界面字体用系统自带的宋体 / 楷体。纯程序贴图的材质偏「塑料」，所以地表、木、石、灰泥、树皮等改用 Poly Haven 的 CC0 扫描贴图（`public/assets/tex/`，来源见其中的 `CREDITS.md`）。只收 CC0，别的授权不要引入。
- **模型精细度是硬上限。** 光影可以做到接近 3A 的观感，但模型是代码堆出来的，达不到美术团队手工雕刻的水平。这一点立项时就向需求方说明过。

## 2. 美术方向是怎么定下来的

人物改过三版，前两版都被否了。README 里的「美术方向」是结论，这里是过程，避免重蹈覆辙：

| 版本 | 做法 | 被否的原因 |
|---|---|---|
| 一 | 胶囊、球体拼成的刚体分节人偶，头大身短 | 「Q 版」「像木偶，不像真人」 |
| 二 | 八头身蒙皮躯体，白衣渐染长袍、玉冠、披肩长发 | 「偏仙侠而非武侠」「美男娘炮」，且发际线太高像秃顶 |
| 三（现行） | 斗笠、粗布短褐、敞襟赤臂、缠臂绑腿、布鞋、酒葫芦，宽肩厚胸 | — |

从中得到的经验：

- **验收的人会把图集放大到好几倍看**，不只是看游戏里 90 像素高的小人。所以「反正游戏里看不清」不成立，手、脚、发际线这些都要经得起放大。
- 「木偶感」主要来自三件事：肢体是分开的刚体段、表面是没有起伏的圆柱、材质是没有纹理的纯色。对应的解法是蒙皮连续曲面、按肌肉走向调截面环、给布料和皮肤画明暗贴图。
- 45° 俯视下**头顶是最显眼的部位**。头发和脸很难做好，斗笠直接把问题盖住，还成了角色标志。
- 四足动物经历了同样的过程（刚体分节 → 蒙皮），现在仍是全项目里最弱的美术，见第 7 节。
- **画面基调是「整体压暗、保留昼夜」**（需求方选定）：白天阴沉、低饱和、明暗对比强，黄昏与夜晚靠灯火。调参时环境光要一直压得很低——暗部沉不下去，灯火和光束就显不出来。
- **不要法术特效**（需求方原话：「不需要魔法和夸张的招式特效，只要简单的冷兵器刀光剑影」）。出招只有刃尖的细弧、火星、扬尘；升级、打坐、用药都不再冒光。目标圈、点击标记是操作提示，保留但做成不发光的细线圈。

## 3. 渲染是怎么搭起来的

**建模代码原本是为离线烘焙写的，现在直接在运行时用。** `src/models/` 里的人形、四足、建筑、树木都是 three.js 的网格与骨架，动画是「相位 → 姿势」的函数。以前把它们逐帧渲染成贴图，现在每帧直接求值，所以动作是连续的（不再是每秒十来帧的抽帧），朝向也是连续的（不再量化到 8 个方向；`Entity.dir` 只留给逻辑用，画面用 `Entity.yaw`）。

**一帧的流程**（`renderer.ts` → `post.ts`）：
1. 阴影贴图：主光一张 4096 的正交阴影（跟随注视点、按贴图像素对齐），外加最多三盏点光源的立方体阴影。
2. 场景渲染到带深度纹理的 HDR 缓冲（4× 多重采样）。光照是 three 自带的前向 PBR：主光 + 半球环境光 + 环境贴图 + 12 盏点光源。
3. 后期全部只依赖颜色与深度：环境光遮蔽（法线由深度重建）→ 体积雾 → 合成 → 泛光 → 色调映射、调色、暗角、颗粒。

**为什么后期只用深度、不用法线缓冲**：场景里有实例化、蒙皮、打了着色器补丁的各种材质，用覆盖材质再渲染一遍法线很容易和主画面对不上；从深度重建法线则与材质无关。

**点光源是一个固定大小的池子**（3 盏带阴影 + 9 盏不带）。three 的着色器把灯的数量编译成常量，灯数一变所有材质都要重编译，会卡一下。所以池里的灯永远在场景里，没用到的强度为 0；游戏每帧用 `r.light(key, …)` 申请，按「亮度 × 半径 ÷ 到注视点的距离」打分分配槽位，`key` 让同一盏灯在帧间留在同一个槽里，换手时有 0.2 秒左右的淡入淡出。

**昼夜的主光是会转的。** 白天太阳东升西落，夜里换成从北面照过来的月亮（人与屋舍多是逆光的剪影）。日月在日出、日落两个时刻交接，这两个时刻主光强度压到近乎为零，方向突变看不出来（`fx.ts` 的 `DAWN` / `DUSK`）。

**体积雾一遍做三件事**（半分辨率，16 步）：贴地流动的雾气；沿视线逐步查主光阴影贴图得到的光束；点光源在雾里的光晕（对 1/d² 沿视线的解析积分，不用步进）。

**静态物件**：每种物件只建模一次，压平成「按材质合并的几何体」，再按 24 米的地块做实例化（`statics.ts`）。地图里带 `f` 的物件用一份沿 X 镜像的几何体；树木花草按位置的哈希值绕竖轴转一个固定角度，打破重复感（建筑和道具不转，它们的碰撞矩形不是正方形）。

**人走到树冠、屋檐后面时**，镜头与主角连线附近的静态物件用抖动的方式挖空（材质补丁里的 `uHole*`）。阴影不受影响，因为阴影用的是另一套深度材质。

**地表**是一张 0.5 米一格的网格，水域按水深下陷成河床，水面是盖在上面的一张反光平面。五层 PBR 贴图装在两个纹理数组里（颜色一个、法线 + 粗糙度一个）——如果每层每张图各占一个采样器，加上阴影贴图会超过片元着色器 16 个采样器的上限。

## 4. 踩过的坑

### 性能（都是量出来的，不是猜的）

- **建模代码的面数是按离线渲染给的。** 一棵枫树两万片叶子、近三十万个三角形，全图七百棵树，第一版每帧 2680 万个三角形。现在叶片按「连通块 = 一片叶子」拆开，每三四片留一片并放大（`thinLeaves`），阴影里再换成每撮叶子一个三角形的代理网格。
- **阴影通道要单独精简。** 阴影里不分材质，所以每种物件的所有投影部件并成一个只含位置的代理网格（材质 `colorWrite: false`，主画面里什么都不写）；花草不投影。
- **`frustumCulled = false` 在有点光源阴影时代价极大**：立方体阴影的六个面、每盏灯都会把它画一遍。蒙皮网格和布料的包围球会随姿势变，所以给它们一个罩住全身的固定包围球，而不是关掉裁剪。
- **人物要合并网格。** 建模时每个部件都是独立网格，一个人四五十次绘制。现在挂在骨骼上的刚体部件改成「权重 1 绑在那根骨骼上」的蒙皮，与同材质的蒙皮网格并成一个；整个人再并一份阴影代理（`actors.ts` 的 `consolidate`）。布料、穗子、弓弦这些每帧自己改形状的保持原样——新增这类部件时要确认它在 `dynamic` 集合里，否则会被烘死在绑定姿势上。
- **布料解算是 CPU 大户。** 离线预演时每步迭代 10 次、步长 1/120 秒；实时改成每帧一步、迭代 4 次（`skin.ts` 的 `SIM`），并去掉了内层循环里的 `Math.hypot` 和数组解构。长袍 NPC 从每人 2.7 毫秒降到 0.25 毫秒左右。
- **点光源阴影轮流更新**：离注视点最近的一盏每帧更新，其余隔帧轮换。远处的灯（离注视点 26 米外）不分配阴影槽位。
- 帧率的参考值：村庄白天与夜晚 60，山寨夜战（十来个人形 + 三盏投影灯）在机器空闲时 60、机器繁忙时掉到 40 上下（1600×900，Apple M4）。量帧率时注意本机负载，`tools/shot.mjs --fps` 的读数在负载高时会低很多。

### 渲染

- **splat 图不能过 2D 画布。** 它的 alpha 通道是「落叶」层的权重，大片为 0；画布内部是预乘 alpha 的，RGB 会被清掉，表现为石板和土路全部消失。现在直接把位图交给 GPU。需要在 CPU 上读像素的只有 aux 图（alpha 恒为 1，没有这个问题）。
- **点光源的衰减改过。** three 默认是纯平方反比，贴着灯的墙面会过曝成一片白；现在在着色器片段里换成带软核的 `1 / (d² + 0.8)`（`renderer.ts` 顶部）。升级 three 后如果灯光突然变得很刺眼，先看这段字符串替换是否还匹配得上。
- **后期着色器用 `RawShaderMaterial`。** 用 `ShaderMaterial` 加 GLSL3 时，three 会自己声明一个片元输出，和着色器里的 `out` 冲突。
- **主光阴影贴图在 PCF 模式下是带比较函数的深度纹理**，在自己的着色器里要声明成 `sampler2DShadow`（体积雾的光束就是这么查的）。
- 静态物件的材质是原材质的副本（`Statics.own`）。挖空与摆动的补丁如果打在原材质上，会波及与之共用材质的人物和兵器。
- 雾的「散射亮度」很容易调过头：黄昏时太阳低、光束项乘上来，整个画面会糊成一片橙色。`KEYS` 里的 `fog` 是散射进来的光，不是雾的颜色，数值要比直觉小得多。
- 用了 CC0 贴图的材质，颜色是「想要的色调 ÷ 贴图平均色」（`geo.ts` 的 `pbrTint`），所以贴图必须在建模之前加载完（`main.ts` 里先 `loadPbr`）。换贴图后要把新的平均色更新到 `PBR_AVG`，否则整体会偏色。

### 建模

- **带缩放的蒙皮网格，绑定前必须先更新世界矩阵**（`humanoid.ts` 的 `skin()`）。否则骨骼逆矩阵和绑定矩阵不在同一空间，缩放不为 1 的角色（村童）会整个扭曲，而其他角色完全正常。
- 宽而扁的飘带用 `Ribbon`（质点链 + 扁管）会拧成锯齿状，围巾这类宽布条要用 `Cloth`（质点网格）。`Ribbon` 只适合发丝、细带。
- 长袍下摆是三片布。片与片之间如果正好对缝，胯部会露出一个黑三角，所以前两片要压住后片一截、半径略大几毫米。
- 布料与穗子的「迎面风」现在取自角色的真实速度（`actors.ts`），不再用各动画里写死的 `wind`。

### 运行时

- 镜头是 30° 的窄视场、50° 俯角，接近等距视角但保留透视。可以放大到 2.2 倍看特写（模型经得起，不再受贴图分辨率限制）。
- 所有模型在启动时建好（约 2–3 秒，进度条在走）。角色的骨架是走进视野才建的，第一次遇到一种新怪会有一帧的停顿。

### 地图

- **桥曾经没搭到对岸，整个河东都走不过去**，截图上还看不出来。之后加了 `tools/map/check-map.mjs`，改完地图一定要跑。现在河道在桥位处是特意收窄、岸线取直的。
- 地图生成是带固定种子的伪随机，改动摆放逻辑里**任何一处**随机数的调用次数，后面所有树和石头的位置都会变。
- 碰撞与灯光不写在地图文件里，而是来自建模代码给出的 `info`（`solid`、`lights`、`deck`、`walk`、`fires`、`door`）。好处是改了建筑后碰撞自动跟上；代价是这套字段没有类型约束，改名要全局搜。因为 `info` 要建模后才有，地图校验脚本是在无头浏览器里把游戏真跑起来查的。

## 5. 怎么验证改动

没有自动化测试，靠的是「无头浏览器里真跑 + 截图用眼看」：

- **`tools/shot.mjs`** 会起一个开发服务器，在无头 Chrome 里打开游戏并截图。配合 `--eval` 可以直接驱动游戏对象（页面上暴露了 `window.game`），例如把角色传到某处、选中最近的敌人打十秒、再把修为和背包读回来。这是目前唯一的回归手段。`--fps` 会顺带量帧率。
- 地址栏参数：`autostart`（跳过标题画面）、`nosave`（清存档）、`x` / `z`（出生位置）、`hour`（时辰）、`zoom`、`scale`（渲染分辨率倍率）、`msaa`（多重采样数）、`sl` / `pl`（带阴影 / 不带阴影的点光源槽位数）。后四个是排查性能用的。
- `window.game.r.debug = 1 / 2 / 3` 分别显示环境光遮蔽、雾的散射光、雾的透过率。
- `window.game.r.gl.info.render` 里有上一帧的绘制调用数与三角形数（含阴影通道）。
- 想截到出招中途的画面：在 `--eval` 里轮询 `pe.atkT / pe.atkDur`，到了想要的相位就把 `game.paused` 设为 true，并把 `r.render` 包一层让它的 `dt` 恒为 0（否则刀光会在截图前淡掉）。
- 光影要在不同时辰各看一眼：正午、黄昏（17–18.5）、深夜、清晨（6.5–7）。只看白天会漏掉雾和灯火的问题。
- 截图与地图校验都依赖本机的 Chrome，路径不在默认位置时用环境变量 `CHROME_PATH` 指定。

## 6. 数值上的意图

数值没有经过完整通关的校准，只保证了方向正确：

- 修为增长：越高越慢，且**对手的品阶远低于自己时几乎不涨**。这是玩法的核心，木人桩因此只适合入门。
- 现实约 5 分半钟长一岁，一个昼夜约 15 分钟。都是为了 demo 压缩过的。
- 1 级角色进黑风寨会在几秒内被打死，这是有意的；但中后期的难度曲线（尤其是寨主战）没人实际打过。

## 7. 还欠着的

- **音效和配乐没有人听过。** 它们是程序合成的，开发全程在无头环境里，只确认了不报错。
- **没有人手动完整通关过**，八段主线只用脚本逐段验证了流程；改成实时 3D 之后只用脚本回归了击杀、拾取、换兵器、打坐。
- 动物仍然偏简化：腿根与躯干有折痕，倒地是整体侧翻；鸡和木人桩还是刚体。动物的网格没有像人形那样合并。
- CC0 贴图只接到了地表、建筑与道具的木石灰泥、树皮。岩石、人物的衣料皮革、兵器的钢面还是程序贴图（贴图已经下好：`rock`、`linen`、`leather`、`steel`）。
- 屋瓦仍是程序贴图：瓦垄是几何体，贴图要对着 UV 画，扫描贴图套不上。
- 悬停高亮没有了（原来是精灵整体提亮），现在只靠脚下的圈；受击闪白换成了击中处的一闪点光。
- 尸体是沉入地面消失的，不是淡出（共用材质做不了逐个角色的透明度）。
- 走出视野很久的角色只是隐藏并从场景里摘掉，几何体没有显式释放。
- 只在一台 Apple M4 上跑过，没有画质档位，也没有移动端和触屏支持。
- 贴图约 27MB（其中法线图 21MB，近无损）直接提交在仓库里。
